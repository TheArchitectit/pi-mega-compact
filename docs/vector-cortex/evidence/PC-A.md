## Evaluation

- The message-separation path is READ-ONLY in-memory prompt reshaping: it reorders existing message references by role and returns a new array (or the identical reference on no-op) — it never mutates a message, never writes state, never reads network (PREVENT-PI-004), and the fixtures carry role names + structural metadata only, never message content (EVAL-REDACT-002).
- `MEGACOMPACT_MESSAGE_SEPARATION=0` is byte-identical to the pre-change OFF state: the call-site gate in `tailResult.ts` never invokes `buildSeparatedPrompt` when `config.messageSeparation` is false, so prompt arrays pass through `tailResult.ts` unchanged. Because the gate now lives at a single place (config-driven, positive flag default ON), the double-gate that previously required BOTH the env var AND `config.messageSeparation` is eliminated.
- The mega-config delegate-shell split is a pure type move: `loadConfig()` returns the same shape and every existing import resolves (build + full suite green), pinned by fixture 004 and `mega-config-types.ts`'s `import type` cross-reference (no runtime cycle).
- **Forced deviation — `extensions/mega-compact.test/s29-percent.test.ts`:** with `messageSeparation` now defaulting ON, the no-trim context-event path in `context-handler.ts` returns a pass-through `{messages}` tail view instead of `undefined` (because `buildTailResult` no longer short-circuits when the flag is on). The S29 percent-gate tests isolate the compaction PERCENT gate and asserted the no-trim path returned no result object; under default-ON they deterministically failed 2/4. Fix: pin `MEGACOMPACT_MESSAGE_SEPARATION=0` inside the `s29TieredCtx` helper so those percent-isolation tests keep their pre-PC-A byte-parity intent. This is a direct, intended consequence of the flag flip (default ON changes the tail-result return shape), not a regression in compaction logic. Added to the spec's Production ownership as a forced-deviation note for controller ratification.

- **No-trim return-shape change:** because the flag now defaults ON, the context handler returns a `{messages}` tail view on the no-trim path more often than before (a pass-through of the unchanged array). This is the flag's intended effect, but downstream consumers that treated a `undefined` return as "no trim" may observe the shape difference; the S29 percent tests were the only affected suite and are pinned to flag-off parity. Flag-OFF restores the prior return shape exactly.
- **Fixture runtime behavior not re-executed by the aggregator:** following the VC9D precedent, the src-hosted aggregator pins fixture integrity + the semantic matrix, while the concrete `buildSeparatedPrompt` reorder is pinned by the extension-level `phase2-separation.test.ts`.
