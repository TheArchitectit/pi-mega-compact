## Evaluation

- The cache-striping path is READ-ONLY in-memory prompt reshaping: `buildCacheOptimizedPrompt` builds a new 5-layer prompt array by inserting a stripe user-message between the summary layer and the thread — it never mutates an existing message, never writes state, never reads network (PREVENT-PI-004), and the fixtures carry layer-name + structural metadata only, never message content (EVAL-REDACT-002).
- `MEGACOMPACT_CACHE_STRIPING=0` is byte-identical to the pre-change OFF state: the call-site gate in `tailResult.ts` never invokes `buildCacheOptimizedPrompt` when `config.cacheStriping` is false; with `messageSeparation` on (the default) only `buildSeparatedPrompt` runs, so the result equals the PC-A-only output byte-for-byte. Because the gate now lives at a single place (config-driven, positive flag default ON), the double-gate that previously required BOTH the env var AND `config.cacheStriping` is eliminated.
- With the flag ON but no `cache_stripes` rows for the current epoch, `buildCacheOptimizedPrompt` inserts an empty stripe layer and returns the base separated prompt unchanged — byte-identical to the PC-A behavior (fixture 006). This is the function's normal path (a pure function: same inputs → same output, no env read).
- The delegation-chain correctness worlds because `buildCacheOptimizedPrompt` reuses the PC-A-unified pure `buildSeparatedPrompt`, then inserts the stripe layer by counting leading summary layers — no duplicated separation logic, no new env reads.
- **Forced deviation — `extensions/mega-compact.test/s29-percent.test.ts`:** with `cacheStriping` now defaulting ON and taking precedence over `messageSeparation` in the tail-result gate (`tailResult.ts:47`), the no-trim context-event path returns a pass-through `{messages}` view (via `buildCacheOptimizedPrompt`) instead of `undefined`. The S29 percent-gate isolation tests asserted the no-trim path returned no result object; under default-ON they deterministically failed 2/4 (tests 1 and 2's no-trim assertions). This mirrors the exact consequence of PC-A's messageSeparation flip on the same file. Fix: pin `MEGACOMPACT_CACHE_STRIPING=0` inside the `s29TieredCtx` helper (alongside the PC-A `MEGACOMPACT_MESSAGE_SEPARATION=0` pin) so those percent-isolation tests keep their byte-identical no-trim intent. Verified load-bearing: default runs 2/4 fail, `MEGACOMPACT_CACHE_STRIPING=0` runs 4/4 pass; the fix restores 4/4. Added to the spec's Production ownership as a forced-deviation note for controller ratification (PC-A's analogous amendment was ratified in the PC-A attestation).

## Residual risks

- **Stripe-layer fallback not re-executed by the aggregator:** following the PC-A/VC9D precedent, the src-hosted aggregator pins fixture integrity + the semantic matrix, while the concrete `buildCacheOptimizedPrompt` layer insertion is pinned by the extension-level `separated-prompt.test` suite. A future refactor that changed the layer insertion but kept fixtures intact would be caught by that suite, not the aggregator.
- **Stripe content loads chunk text from `context_chunks`:** when stripe rows exist, the function loads `normalized_text` per chunk to assemble the stripe user-message. This is local-only and best-effort (a missing chunk just skips that block), but it means the flag-on output size depends on the store's stripe state — behavior varies with data, not with the environment variable. Flag-OFF and no-stripe paths are deterministic.
