# ENC-2c — Lazy-download native ORT upgrade

**Status:** planned | **Depends on:** ENC-2a (artifacts module + install script), ENC-2b (qualification retest), ENC-1b (runtime selection) | **Phase:** ENC
**Flag:** `MEGACOMPACT_ENC_2C`, defined in `src/config/vector-cortex-enc2c.ts` (sibling extract), re-exported by `vector-cortex.ts` + root `src/config.ts`, default ON; `MEGACOMPACT_ENC_2C=0` disables and must be byte-identical to the predecessor — the lazy-download path is absent, the GET omits all new download fields, and the Cortex sub-tab renders the ENC-2a copy-paste guide card (not the lazy-download card). Registered in `VECTOR_CORTEX_SETTINGS` as a visible boolDirect toggle, never in `EXCLUDED_SETTINGS`.

## Goal and inputs/outputs

**Upgrade from the operator-managed copy-paste install (ENC-2a) to an in-extension lazy-download that installs `onnxruntime-node` on first native-encoder use, then triggers the ENC-2b retest.** When `encoderNativeOptIn: true` and `encoderBackend: "wasm"` (the ENC-1b selection demoted because `onnxruntime-node` is absent), AND the operator has not run the ENC-2a install script, the extension downloads the pinned `onnxruntime-node` tarball from the npm registry, verifies its SHA-256 against the pinned artifact (from `src/vector-cortex/encoder/native-install-artifacts.ts`), unpacks it into `~/.pi/mega-compact/native-ort/` (the same path ENC-2a uses), and then runs the ENC-2b qualification retest to produce a fresh verdict. The download is user-consented via a POST action key (same confirmation pattern as VC9B/ENC-2a); the extension NEVER auto-downloads without explicit operator confirmation.

This sprint requires a **PREVENT-PI-004 network exception** — the extension fetches the npm-registry tarball at runtime. This is a new network path (not one of the existing exceptions). The exception is gated behind `MEGACOMPACT_ENC_2C` (default ON, operator can disable to stay fully offline) and annotated inline with `// guardrails-allow PREVENT-PI-004: ENC-2c lazy-download native ONNX runtime — operator-consented, SHA-256-pinned, npm-registry fetch to ~/.pi/mega-compact/native-ort/`. The guardrails scanner enforces a reason. The exception is audited in the evidence.

Inputs: the ENC-2a artifacts module (pinned version + per-platform tarball URL + SHA-256), the ENC-2b retest module, the ENC-1b selection computation, and the host `detectPlatform()`. Outputs: one additive contract field on the GET read path (`nativeOrtDownloadStatus?: {state: "not_started"|"downloading"|"verifying"|"installed"|"failed", progressPct?: number, error?: string, version?: string}` — absent when flag off OR opt-in off), plus a POST action key `nativeOrtDownload: true` that triggers the lazy download (consented, SHA-verified, then retest).

`MEGACOMPACT_ENC_2C` gate (default ON; `=0` = the lazy-download path is entirely absent, the GET omits `nativeOrtDownloadStatus`, the POST ignores the `nativeOrtDownload` key, and the Cortex sub-tab renders the ENC-2a copy-paste guide card as the install path — byte-identical to the ENC-2b-era shape). When the flag is ON but `encoderNativeOptIn` is OFF, the download path is inert (no download without opt-in).

## Failure triad and independence

A **download round-trip**: when the operator POSTs `nativeOrtDownload: true` with `confirm: true`, the extension fetches the pinned tarball, SHA-256-verifies it, unpacks it to `~/.pi/mega-compact/native-ort/`, and runs the ENC-2b retest — pinned by **ENC-DOWNLOAD-001** (download consent round-trip). B **SHA-256 verification**: the download module asserts the fetched bytes' SHA-256 matches the pinned constant; a mismatch aborts with `state: "failed"` and NO unpack — pinned by **ENC-DOWNLOAD-002** (sha mismatch aborts) and **ENC-DOWNLOAD-003** (sha match proceeds). C **flag-off + absence**: `MEGACOMPACT_ENC_2C=0` omits `nativeOrtDownloadStatus` and the lazy-download card does not render (the ENC-2a copy-paste card is the primary path) — pinned by **ENC-DOWNLOAD-004** (flag-off byte-identical), **ENC-DOWNLOAD-005** (confirm-required), and **ENC-DOWNLOAD-006** (contract additivity). A is produced by the download module; B by the SHA-verify; C by the flag/absence branches. Independence: the download module is isolated from the route layer; the SHA-verify is a pure function; the flag-off path is verified byte-identical.

## PREVENT-PI-004 network exception

This sprint adds a new runtime network path: `fetch()` to the npm registry tarball URL. The exception is:

- **Gated**: behind `MEGACOMPACT_ENC_2C` (default ON, operator can disable to stay fully offline — the ENC-2a copy-paste guide is the fallback).
- **Consented**: the POST requires `confirm: true` (double-confirm pattern); no auto-download.
- **SHA-256-pinned**: the tarball bytes are verified against the pinned constant from `native-install-artifacts.ts`; a mismatch is a zero-tolerance failure.
- **Audited**: the inline annotation `// guardrails-allow PREVENT-PI-004: ENC-2c lazy-download native ONNX runtime — operator-consented, SHA-256-pinned, npm-registry fetch to ~/.pi/mega-compact/native-ort/` is present at the `fetch()` call site.
- **Scoped**: the fetch targets ONLY the pinned tarball URL from the artifacts module; no dynamic URL construction, no user-controlled URL.

The evidence records: the exact `fetch()` call site (file:line), the annotation, the flag gate, the confirm pattern, the SHA-256 verification, and the operator-disable path (`MEGACOMPACT_ENC_2C=0`).

## Tests, fixtures, and assertions

## Migration, privacy, dashboard, and rollback

Migration disposition: **pure — no store/schema changes.** The download status is ephemeral (in-memory during the download, then the probe marker on disk); NO persisted state table. The probe marker path is the same as ENC-2a's (`~/.pi/mega-compact/native-ort/.enc2a-marker.json`), so ENC-2b's reader picks it up unchanged. Privacy follows [SECURITY_PRIVACY](../SECURITY_PRIVACY.md): the download surfaces ONLY the platform, version, status, progress, and error string — NEVER the tarball binary contents, NEVER the binding internals. The npm-registry fetch does NOT send credentials (no auth header; the registry tarball URL is public). Dashboard: the Setup Cortex sub-tab gains the lazy-download card; `cd extensions/dashboard-client && npm run typecheck && npm run build`. NO new route (shared `/api/setup-status` + `/api/setup-configure`). Rollback sets `MEGACOMPACT_ENC_2C=0`; the lazy-download path is absent, the ENC-2a copy-paste guide is the primary install path, byte-identical to the ENC-2b survivor. The operator-installed `native-ort/` dir is NOT deleted (data preservation — same as ENC-2a rollback). No operator migration.
