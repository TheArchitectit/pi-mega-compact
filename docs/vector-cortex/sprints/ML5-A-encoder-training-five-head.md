# ML5-A — Five-head training + calibration corpus build

**Status:** planned | **Depends on:** VC2C | **Phase:** ML5
**Flag:** `MEGACOMPACT_ML5_A`, defined in `src/config/vector-cortex-ml5a.ts` (sibling extract), re-exported by `vector-cortex.ts` + root `src/config.ts`, default ON; `MEGACOMPACT_ML5_A=0` disables and must be byte-identical to the pre-ML5-A state (mode B trigram continues serving; the code path is unchanged). ## Goal and inputs/outputs

Close **HG-1 partial** (corpus build + first five-head fit) by producing real trained head weights on a frozen BGE-small-int8-ONNX trunk, replacing the VC2B/VC2C placeholder stubs. The committed `model.onnx` is currently a **42-byte placeholder** generated by `scripts/vector-cortex-gen-assets.mjs` (digest-covered, opset 17); the five heads are currently **LCG fake projections** (`heads.ts:11,48`, state `*1664525+1013904223`), and `calibrate.ts:87,126` ships **placeholder thresholds** carrying the comment *"This frozen threshold is a normative placeholder"*. ML5-A is the sprint that turns these normative placeholders into learned weights.

The five-head encoder: **semantic(384) / dependency(128) / contradiction(128) / cache-stability(64) / payload-routing(32)**, all L2-normalized, trained jointly on the **frozen BGE-small-int8-ONNX trunk** with loss weights **.35/.20/.20/.15/.10**, seed **1729**. Trunk = `Xenova/bge-small-en-v1.5` (MIT, 33.4M params, prebuilt int8 ONNX ~23 MiB, 384-dim, 512-seq). **No pretrained shortcut heads exist** — all five are trained from scratch using supervision transfer where teachers exist: contradiction ← NLI-distill (from `cross-encoder/nli-deberta-v3-small`); dependency ← NLI-entailment prior + self-labeled pairs; cache-stability ← deterministic heuristic features (no teacher needed); payload-routing ← tiny MLP on trunk embedding; semantic ← trunk output directly, calibrated.

**This sprint is Python-side ONLY by design (design constraint 1).** `training/vector-cortex/{train.py,export_onnx.py,calibrate.py}` run locally on the host where the corpus lives, using PyTorch / `optimum[onnxruntime]`. They are **not** part of the extension runtime — `src/`/`extensions/` never import them, no new runtime dependency is added, and **PREVENT-PI-004 stays green**. pip install is setup-time, not runtime (design constraint 6).

Determinism (design constraint 2): **seed 1729 everywhere** — Python, NumPy, PyTorch, and ONNX export. The same corpus always produces the same SHA-256 of the output `.onnx`. The corpus (design constraint 3) is the extension's own SQLite `context_chunks` / `turns` / `conversations` tables, filtered to **redacted-tagged rows only**, grouped by **repo+session** for stable reproducible splits (matching VC2C's `calibrate.ts` grouping). Corpus snapshot digest (SHA-256) is the training set's identity, written to the provenance ledger (phase invariant 6). Export (design constraint 4): `optimum.onnxruntime` with opset **17**, int8 quantization; output = trained-head weights appended to the frozen trunk ONNX (~23.5 MiB total int8, opset 17 closing VC2 §5) + `tokenizer.json`. Calibration (design constraint 5): per-head temperature + threshold fit on a held-out calibration split, written as `CalibrationV1` JSON consumed by `src/vector-cortex/encoder/calibrate.ts` — replacing the placeholder `fitTemperature`/`fitThreshold` and the normative-placeholder comment.

The **meaningful** deliverable is the learned Mode-A asset; the conformance fixtures (ML5-TRAIN-001..006) pin the corpus-split invariants, deterministic export, loss weights, seed pinning, corpus digest, and calibration shape so the loop is reproducible. The runtime decision (ML5-C) and eval harness (ML5-B) are separate later sprints — ML5-A does **not** select ONNX Runtime for the extension, does not touch the dashboard, and does not promote mode A (still mode B until ML5-B/C validate + a sweep of the bench gates).

## Failure triad and independence

A flag-on with real asset: with `MEGACOMPACT_ML5_A=1` (default), the training pipeline produces a real weighted asset — `calibrate.ts`/`heads.ts` read real `CalibrationV1`/head weights, and the six conformance fixtures pass (fixture ML5-TRAIN-001). B empty/corpus-less: with the flag on but a fresh/no corpus (no redacted-tagged rows yet), the pipeline no-ops gracefully — no asset is emitted, `calibrate.ts`/`heads.ts` continue serving the placeholder behavior, and the code path is byte-identical to pre-ML5-A (fixture ML5-TRAIN-003). C flag-off: with `MEGACOMPACT_ML5_A=0`, the training pipeline is disabled and both `calibrate.ts` and `heads.ts` are byte-identical to the VC2C-era placeholder state — mode B trigram continues serving, no code path change (fixture ML5-TRAIN-003's flag-off branch). Deterministic export (fixture ML5-TRAIN-002), loss-weight pinning (fixture ML5-TRAIN-004), seed pinning (fixture ML5-TRAIN-005) and corpus-digest identity (fixture ML5-TRAIN-006) are pinned by the remaining fixtures. A is produced by the real training + weight load; B by the empty-corpus early return; C purely by the flag branch. All three use independent inputs. Common cooldown/spool/restart/clock rules are normative in [TRIAD_RESILIENCE](../TRIAD_RESILIENCE.md).
