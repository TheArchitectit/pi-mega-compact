## Goal and inputs/outputs

**Two surfaces, one Settings sprint.** (A) **Embedder API completion**: ENC-1a surfaced only `MEGACOMPACT_EMBEDDING_URL` + `MEGACOMPACT_EMBEDDING_KEY`. This sprint adds the three remaining env vars the runtime reads (`src/httpEmbedder.ts:embeddingConfigFromEnv`) to the Settings surface: `MEGACOMPACT_EMBEDDING_DIM` (numeric, validated positive int bounded by a new constant), `MEGACOMPACT_EMBEDDING_HEADERS` (JSON object string — secret-bearing, written verbatim to `.mega-compact.env`, never echoed raw), and a boolDirect toggle for `MEGACOMPACT_ALLOW_REMOTE_EMBEDDER` (default off — a deliberate escape hatch; the toggle flips the persisted env line). (B) **ONNX runtime selection surface**: the existing knob `MEGACOMPACT_ENCODER_NATIVE` (`src/vector-cortex/encoder/runtime-select.ts`) currently requires hand-set shell env with no dashboard visibility. This sprint persists that knob to `.mega-compact.env` via the same writer, exposes a Settings toggle, and surfaces the **current effective backend** (`wasm` | `native`) plus an optional `demotionReason` — computed live through the EXISTING `selectRuntimeBackend`, reader-only, no literals in the route. **No changes to runtime-selection semantics** — this is visibility + persistence of a knob that already exists.

Inputs: the three new embedder fields (dim / headers / allow-remote) + the Cortex native opt-in toggle. Outputs: four additive contract fields on the `GET /api/setup-status` read path (`embeddingDim?: string`, `embeddingHeadersSet?: boolean`, `allowRemoteEmbedder?: boolean`, and the Cortex trio `encoderNativeOptIn?: boolean`, `encoderBackend?: "wasm" | "native"`, `encoderDemotionReason?: string | null`), the additive writer branch on `POST /api/setup-configure` accepting `{ embeddingDim?, embeddingHeaders?, allowRemoteEmbedder?, encoderNativeOptIn? }`, and the UI rows on the dashboard.

`MEGACOMPACT_ENC_1B` gate (default ON; `=0` = the Settings UI renders only the pre-existing ENC-1a-era fields + existing toggles, the GET body omits all new fields, and the POST handler ignores/returns 404 on the new payload keys — byte-identical to the ENC-1a shape). ## Failure triad and independence

A persisted round-trip: POSTing `{embeddingDim:"384", embeddingHeaders:'{"x-extra":"1"}', allowRemoteEmbedder:true, encoderNativeOptIn:true}` writes four lines to `.mega-compact.env`, and the next GET returns `{embeddingDim:"384", embeddingHeadersSet:true, allowRemoteEmbedder:true, encoderNativeOptIn:true, encoderBackend:<wasm|native>, encoderDemotionReason:<string|null>}` — pinned by **ENC-ONNX-001** (dim persisted + echoed) and **ENC-ONNX-004** (native opt-in round-trip + effective backend surfaced with demotionReason when fallback occurs). B secret-redaction: the raw headers JSON object is written to the disk file but NEVER echoed back in any GET response — the GET returns only `embeddingHeadersSet:true` — and invalid-header JSON is rejected with 400 + `invalid_embedding_headers` with the file left byte-unchanged — pinned by **ENC-ONNX-002**. C boolean round-trips: `allowRemoteEmbedder` defaults to off (absent line → `false`) and round-trips through the toggle — pinned by **ENC-ONNX-003**. Contract additivity (pre-ENC-1b clients that omit the new keys validate unchanged) is pinned by **ENC-ONNX-005**; flag-off (GET omits all new fields, POST with the new keys → disabled/404, byte-identical predecessor) by **ENC-ONNX-006**. A is produced by the writer + reader round-trip; B purely by the validation + redaction branches; C purely by the default-off + toggle branches. `MEGACOMPACT_ENC_1B=0` is byte-identical to the ENC-1a survivor. Common cooldown/spool/restart/clock rules are normative in [TRIAD_RESILIENCE](../TRIAD_RESILIENCE.md).

## Migration, privacy, dashboard, and rollback

Migration disposition: **pure — no store/schema changes.** The four values persist in the per-repo `.mega-compact.env` text file (the existing per-repo state-dir mechanism), NOT in SQLite; the store schema and `stateDir` tables are untouched. Privacy follows [SECURITY_PRIVACY](../SECURITY_PRIVACY.md) and imposes the same **never-echo rule on the headers JSON as on the API key**: `MEGACOMPACT_EMBEDDING_HEADERS` may carry secrets (e.g. an Authorization header for TEI), so the raw value is written to the disk file and to `process.env` on load (**never** echoed to the dashboard GET client, **never** emitted in any event, **never** logged) — the GET reports only the boolean `embeddingHeadersSet`. The `MEGACOMPACT_ALLOW_REMOTE_EMBEDDER` toggle defaults OFF because it is a deliberate escape hatch that skips the loopback-only check in `embeddingConfigFromEnv`; flipping it ON is an explicit, persisted user decision, and the UI labels it as such. Dashboard: the Setup Embedder surface + the Cortex sub-tab are touched — owned files above under `extensions/` + client cards; the additively-extended `GET /api/setup-status` + `POST /api/setup-configure` are the same two routes, no new routes, no `EXPECTED_ENDPOINT_COUNT` bump; run `cd extensions/dashboard-client && npm run typecheck && npm run build`. Rollback sets `MEGACOMPACT_ENC_1B=0`; the Setup surface renders only the pre-existing ENC-1a-era fields + existing toggles and the routes omit all new fields, byte-identical to the ENC-1a survivor, without deleting the saved `.mega-compact.env` lines (the runtime still reads them — rollback only hides the UI, never silently discards user data). No operator migration.
