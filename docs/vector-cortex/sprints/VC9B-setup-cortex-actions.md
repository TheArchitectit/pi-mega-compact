## Goal and inputs/outputs

Consume the VC9A-established Setup Cortex contracts and [common contracts](../CONTRACTS.md). Own the two action drivers under the existing Setup Cortex route group — the confirmation-gated, hard-gate-aware action endpoints: `POST /api/setup-cortex-action` (body `{action:"fetch-model"|"bench"|"verify-asset", confirm:true}`) and `GET /api/setup-cortex-action-log?name=<logfile>`. Blocked actions (fetch-model/bench, gated by open HG-1 + HG-3) are rejected locally with the open-gate blockers and NEVER spawn a subprocess; verify-asset is NOT gated (pure re-read of the committed asset, no subprocess). Production ownership: `extensions/dashboard-server/routes-setup-cortex-actions.ts; extensions/dashboard-server/setup-cortex-actions.ts; extensions/dashboard-server/routes-setup-cortex-actions.test.ts; extensions/dashboard-server/api-contracts/setup-cortex.ts; extensions/dashboard-server/api-contracts/endpoints/registry-ext.ts; extensions/dashboard-server/setup-cortex-blockers.ts; extensions/dashboard-server/route-dispatch.ts; extensions/dashboard-server/routes.ts; extensions/dashboard-server/api-contracts.test/endpoints-registry.test.ts; src/config/vector-cortex.ts; src/config/vector-cortex-vc9b.ts; src/config.ts; extensions/dashboard-server/routes-rag-settings-vector-cortex.ts; scripts/vc9-setup-dashboard/gen-fixtures-vc9b.mjs; conformance/vector-cortex/v2/setup-dashboard/; conformance/vector-cortex/v2/schemas/setup-cortex-action-fixture.schema.json; conformance/vector-cortex/v2/manifest.json; src/vector-cortex/vc9b-acceptance.test.ts; docs/vector-cortex/sprints/VC9B-setup-cortex-actions.md; docs/vector-cortex/evidence/VC9B.md; scripts/vector-cortex-docs-check.mjs`.

**Forced deviation (code-following, flagged for controller ratification):** the brief stated "VC9A landed at 781 → VC9B lands at 785" and to "reuse" the VC9A `setup-cortex-fixture` schema. The canonical manifest actually lands at **786 fixtures**: the four action fixtures (SETUP-CORTEX-010..013) use a **new sibling schema** `setup-cortex-action-fixture.schema.json` rather than reusing the VC9A reader schema, because the minimal conformance validator has NO `oneOf`/conditional-required support — a `confirm`-rejection action envelope (`{action, confirm:false, error:"confirmation_required", no_spawn:true}`) cannot be expressed by the VC9A status schema (whose required fields are locked to the reader projection) without distorting that schema or weakening its required-field contract. The config automation chose fixture reuse where it is clean (the four action fixtures reuse the VC9A manifest algorithm/schema-seam mechanics unchanged) and a sibling schema where the envelope is genuinely different. Net increase: 30 fixtures (9 VC9A reader fixtures + the new schema consumed by them, +4 action fixtures consumed by the sibling schema) → canonical 786. Recorded in [VC9B Evidence](../evidence/VC9B.md); controller to ratify.

Algorithm: `POST` parses+confirms the body, evaluates `setupCortexActionBlockers(action)` (canonical matrix from `setup-cortex-blockers.ts` — `["HG-1","HG-3"]` for `fetch-model`/`bench`, `[]` for `verify-asset`), and on pass spawns the local script (`scripts/vc2-model-prep/fetch-model.sh` or `bench-onnx.mjs` for the gated pair — spawnSync for a well-bounded, fully local, loopback-only utility with no network, per PREVENT-PI-004; verify-asset runs the real `verifyEncoderAsset` seam, no subprocess) capturing to `<stateDir>/logs/vc9b/<action>-<ts>.log`. `GET` reads a bounded 8 KiB (`ACTION_LOG_TAIL_BYTES`) tail, redacting sha256/base64 payload tokens (never bytes), and basename-validates the name against traversal (`isSafeLogName`, `/^[a-z-]+-\d+\.log$/`). Response shapes per the `api-contracts/setup-cortex.ts` contract: `SetupCortexActionResult {action, ok, exitCode, logPath, logName, spawned}`, `SetupCortexActionBlocked {error:"action_blocked_by_open_item", blockers[]}`, `SetupCortexActionLogResponse {name, tail, complete}`.

A shares the setup-cortex driver + assets; B is produced by the hard-gate matrix before any spawn; C is produced purely by the flag gate. Each uses independent algorithms/assets as applicable.
