# ENC-2b — Native ONNX runtime qualification retest

**Status:** planned | **Depends on:** ENC-2a (install guide + artifacts module), ENC-1b (runtime selection), ENC-0f (RSS/p95 budget) | **Phase:** ENC
**Flag:** `MEGACOMPACT_ENC_2B`, defined in `src/config/vector-cortex-enc2b.ts` (sibling extract), re-exported by `vector-cortex.ts` + root `src/config.ts`, default ON; `MEGACOMPACT_ENC_2B=0` disables and must be byte-identical to the predecessor — the GET omits all new retest fields, the POST ignores retest-request keys, and the Cortex sub-tab renders no retest card. Registered in `VECTOR_CORTEX_SETTINGS` as a visible boolDirect toggle, never in `EXCLUDED_SETTINGS`.

## Goal and inputs/outputs

**Re-probe and re-qualify the native ONNX runtime after the operator installs via the ENC-2a guide.** When the operator runs the install script (or installs `onnxruntime-node` manually into `~/.pi/mega-compact/native-ort/`), the extension's read path does not automatically re-evaluate the qualification verdict — the encoder still reports `encoderBackend: "wasm"` until a retest runs. This sprint delivers the retest: a reader-only qualification probe that detects the installed native binding, runs the ENC-0f RSS/p95 budget against it, computes a fresh qualification verdict, and surfaces the result on the Setup Cortex sub-tab and the GET `/api/setup-status` response.

Inputs: the ENC-2a artifacts module (`src/vector-cortex/encoder/native-install-artifacts.ts` — pinned version + per-platform SHA-256), the ENC-1b `enc1bStatusFields` selection computation, the ENC-0f RSS/p95 budget constants, the host `detectPlatform()`, and the installed binding at `~/.pi/mega-compact/native-ort/node_modules/onnxruntime-node/`. Outputs: two additive contract fields on the GET read path (`nativeOrtRetestResult?: {platform, version, verdict, p95Ms, rssMiB, testedAt} | null` — null when no native binding installed OR flag off — and `nativeOrtBackendEffective?: "native" | "wasm"` reflecting the post-retest effective selection), plus a new POST action key `nativeOrtRetest: true` that triggers the retest synchronously (bounded execution, no network — the binding is already on disk from the operator's ENC-2a install).

`MEGACOMPACT_ENC_2B` gate (default ON; `=0` = the GET omits `nativeOrtRetestResult` and `nativeOrtBackendEffective`, the POST ignores the `nativeOrtRetest` key, byte-identical to the ENC-2a-era shape). The retest NEVER downloads anything (the binding is on disk from ENC-2a); the retest NEVER trains anything (HG-1 unchanged). The retest loads the installed `onnxruntime-node`, runs a bounded warmup + p95 probe (same harness as `scripts/vc2-model-prep/bench-onnx.mjs` but in-process against the real binding), measures RSS via `process.memoryUsage()`, and computes the verdict against the ENC-0f thresholds.

## Failure triad and independence

A **retest round-trip**: when a native binding is present, the GET carries `nativeOrtRetestResult` with a non-null verdict + measured p95/RSS, and `nativeOrtBackendEffective` reflects the verdict — pinned by **ENC-RETEST-001** (binding-present retest round-trip). B **absence semantics**: when no binding is installed, the GET omits `nativeOrtRetestResult` (absent, not null) and the retest card does not render — pinned by **ENC-RETEST-002** (binding-absent retest absent). C **flag-off + failure**: `MEGACOMPACT_ENC_2B=0` omits both new fields byte-identical to ENC-2a-era; a `failed` verdict (binding crashes on load) is surfaced with `nativeOrtBackendEffective: "wasm"` — pinned by **ENC-RETEST-003** (flag-off byte-identical), **ENC-RETEST-004** (failed verdict stays wasm), **ENC-RETEST-005** (POST retest action), and **ENC-RETEST-006** (contract additivity). A is produced by the retest module; B by the absence branch; C by the flag/verdict branches. Independence: the retest module is isolated from the route layer; the GET merge is additive-only; the flag-off path is verified byte-identical.

## Migration, privacy, dashboard, and rollback

Migration disposition: **pure — no store/schema changes.** The retest result is computed on each GET (reader-only, memoized per `enc1bStatusFields` cache key) and returned on the response body; NO persisted state table. The POST retest action is synchronous and stateless (the result is returned on the response, not stored). Privacy follows [SECURITY_PRIVACY](../SECURITY_PRIVACY.md): the retest result surfaces ONLY the platform, version string, verdict, latency, and RSS — NEVER the binding binary contents, NEVER the model weights. Dashboard: the Setup Cortex sub-tab gains the retest card; `cd extensions/dashboard-client && npm run typecheck && npm run build`. NO new route (shared `/api/setup-status` + `/api/setup-configure`). Rollback sets `MEGACOMPACT_ENC_2B=0`; both new fields are omitted, byte-identical to the ENC-2a survivor. No operator migration.

## Hard gates (OPEN per evidence)

The retest does NOT close HG-1 (five-head training — the retest uses the existing placeholder heads, not trained ones). The retest does NOT close HG-4 (darwin-x64 — the retest is conditional on a native binding existing; darwin-x64 hosts have none). The retest CAN partially close HG-3 (native install path verification — the retest proves the installed binding works) and HG-5 (RSS/p95 — the retest measures real p95 and RSS against the ENC-0f budget). Evidence records whether HG-3/HG-5 are fully closed (verdict `qualified`) or remain open (verdict `degraded`/`failed`).
